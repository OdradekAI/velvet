# Domain docs

This repository uses a single domain context.

Before exploring code or making a design decision:

- Read `docs/GLOSSARY.md`.
- Read the relevant ADRs under `docs/adr/`.
- Use the glossary's canonical terms in issue titles, proposals, tests and implementation plans.
- If a new domain concept is needed, sharpen and record it in `docs/GLOSSARY.md`.
- If a proposed change contradicts an ADR, name the conflict explicitly and decide whether the ADR should be reopened.

`docs/GLOSSARY.md` contains domain vocabulary only. Implementation choices belong in ADRs or engineering documents.
